# Workflow Preferences

## Git workflow

- **Skip pull requests.** Commit changes directly and push to `master`.
- No need to create feature branches for each change.
- Just commit with a clear message and push straight to `master`.
- This applies to all changes in this repo regardless of size.

## Reasoning

The project owner prefers the simpler workflow of direct commits over the PR review cycle, since they review changes themselves after each push and test on Replit.
